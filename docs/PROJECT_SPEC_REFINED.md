# [아카이브] 완료된 작업 명세 (Completed Tickets - Frozen)
> 이 섹션의 티켓들은 이미 구현 및 검증이 완료되어 동결(Frozen)된 명세입니다. 추후 이력 확인 및 레퍼런스로 활용하며 임의로 수정하지 않습니다.

## T0101. 실행 가능한 최소 메인 창 [완료]

- **입력:** 프로그램 실행.
- **동작:** 상단 설정 버튼, `[붙여넣기(아이콘)] [URL 입력칸] [다운로드]` 순서로 수평 배치된 입력 영역, 하단 작업 목록 영역이 있는 PyQt6 메인 창을 연다. URL 입력칸에 텍스트가 입력되어 있을 때는 이를 한 번에 지울 수 있는 삭제(Clear) 아이콘이 입력칸 우측 내부에 오버레이된다. 작업 목록 항목은 향후 시계 방향 1~4번 영역(1: 작업명/상태, 2: 액션 아이콘, 3: 진행상태, 4: 쿠키/인증) 레이아웃 구조를 취한다.
- **출력:** URL 입력칸에는 `치지직 VOD URL을 입력하세요`, 작업 목록에는 `작업 없음`이 표시된다.
- **성공 기준:** 한 개의 메인 창이 오류 없이 열리고 `[붙여넣기 아이콘] [URL 입력칸] [다운로드]` 순서로 배치된다. 텍스트 입력 시 삭제 아이콘이 나타나고 클릭 시 입력칸이 비워진다. 아직 구현하지 않은 채널·알림·시스템 영역은 빈 자리나 동작하지 않는 버튼으로 미리 만들지 않는다.

## T0102. URL 입력 정리와 VOD 판별 및 토스트 알림 [완료]

- **입력:** 사용자가 입력한 URL 문자열, 붙여넣기 아이콘 클릭(클립보드 반영), 다운로드 버튼 클릭(또는 URL 입력칸에서 Enter 키 입력).
- **동작:**
  1. 붙여넣기 아이콘 클릭 시 클립보드의 텍스트를 URL 입력칸에 즉시 붙여넣는다.
  2. URL 입력칸에서 마우스 우클릭 시 Non-modal 컨텍스트 메뉴를 표시한다:
     - 구성: `실행 취소`, `다시 실행` / 구분선 / `잘라내기`, `복사`, `붙여넣기`, `붙여넣고 다운로드`, `삭제` / 구분선 / `모두 선택`
     - `붙여넣고 다운로드`: 클립보드 내용을 입력칸에 붙여넣음과 동시에 다운로드 버튼 클릭(VOD 판별)을 연속 트리거한다.
     - `삭제`: 마우스로 블록 지정(선택)된 텍스트를 삭제한다.
  3. URL 입력칸에 입력 후 어떠한 방법(다운로드 버튼 클릭, Enter 키 입력, '붙여넣고 다운로드' 메뉴 등)으로든 다운로드 동작이 트리거되면, URL 입력칸의 텍스트를 즉시 비운다.
  4. URL 입력값의 앞뒤 공백과 줄바꿈을 정리하고 치지직 VOD URL(`https://chzzk.naver.com/video/{videoNo}`)인지 정규식으로 검증한다.
  5. 빈 값(공백 포함)인 경우 검증 및 토스트 노출 없이 동작을 무시한다. 그 외 다른 사이트·유사 도메인·ID 없는 잘못된 URL은 네트워크 요청 없이 즉시 실패 처리한다.
  6. 정상 VOD URL인 경우 QThread를 통해 백그라운드에서 치지직 VOD API(`GET https://api.chzzk.naver.com/service/v3/videos/{videoNo}`)를 요청하여 실제 제목과 VOD ID를 확인한다.
- **출력 (오버레이 토스트 노출 및 소멸 규칙):**
  - **URL 추가 및 다운로드 동작 토스트**:
    - URL 입력 후 다운로드 버튼 활성화/동작 시: 반투명 검은색 오버레이 배경에 `+(파란색) [URL(흰색)]` 형식의 토스트가 노출되고 설정된 시간(기본 2초, 상수로 분리하여 조율 가능) 후 자동으로 사라진다.
    - 정상 동작 시 별도의 성공 텍스트 토스트는 노출하지 않고 이 토스트로 갈음한다.
  - **실패 토스트**:
    - 유효하지 않은 URL인 경우 `지원하지 않는 URL`, 네트워크·서버·응답 오류인 경우 `VOD 확인 실패`와 이유가 빨간색 오버레이 토스트로 표시된다.
    - 사용자가 명시적으로 클릭하거나 새로운 요청(다운로드 버튼 클릭)이 시작될 때 사라진다.
- **성공 기준:**
  - 붙여넣기 아이콘 클릭 시 클립보드 텍스트가 URL 입력칸에 정상 입력된다.
  - URL 입력칸 우클릭 시 Non-modal 메뉴가 정상 표시되고 각 동작이 실행된다.
  - 다운로드 동작이 트리거되면 URL 입력칸이 즉시 비워진다.
  - 정상 URL 처리 시 `+(파란색) [URL(흰색)]` 반투명 검은색 토스트가 노출되고 2초 후 자동 소멸한다.
  - 실패한 경우에만 별도의 실패 토스트가 출력되며, 명시적 클릭이나 새 요청 시작 전까지 유지된다.
  - QThread 기반 비동기 처리로 API 조회 중에도 GUI가 멈추지 않는다.

## T0103. VOD 정보 조회용 yt-dlp 확인 [완료]

- **입력:** 앱 의존성에 추가된 yt-dlp 공식 Python 패키지 및 치지직 VOD URL.
- **동작:**
  1. `pyproject.toml`에 `yt-dlp` 공식 라이브러리를 추가하고 패키지 로드 가능 여부를 검증한다.
  2. T0102의 직접 치지직 REST API 의존성을 완전히 제거하고, `yt_dlp.YoutubeDL(opts).extract_info(url, download=False)` 기반의 VOD 메타데이터 조회 모듈로 전면 교체한다.
  3. `extract_info` 결과에서 제목(`title`), 채널/스트리머명(`channel` 또는 `uploader`), VOD ID(`id`), 썸네일(`thumbnail`), 전체 재생 시간(`duration`), 실제 제공 품질 목록(`formats`)을 포함하는 데이터 모델(`VodInfo`)을 추출한다.
  4. 패키지 로드 불가 또는 조회 실패(`DownloadError`, 네트워크 단절, 비공개/삭제된 영상 등) 발생 시 오류를 포착하여 도구명(`yt-dlp`), 버전 및 구체적 사유를 실패 토스트에 전달한다.
- **출력:**
  - 정상 동작 시: yt-dlp를 통해 VOD 메타데이터(제목, 채널명, 품질 목록 등) 조회가 완료되고, T0102의 `+(파란색) [URL(흰색)]` 반투명 토스트가 유지된다. 정상 시에는 UI에 yt-dlp 버전을 불필요하게 노출하지 않는다.
  - 오류 발생 시: 도구명(`yt-dlp`)과 에러 원인이 명시된 빨간색 실패 토스트가 출력된다.
- **성공 기준:**
  - 치지직 VOD URL의 제목 및 메타데이터 조회가 `yt-dlp` 공식 Python API를 통해 정상 동작한다.
  - T0102의 직접 치지직 REST API 호출 코드는 완전히 제거된다.
  - 패키지 로드 오류나 추출 실패 시에도 앱이 강제 종료되지 않고 실패 토스트가 정상 안내된다.
  - 사용자가 별도의 `yt-dlp.exe` 실행 파일 경로를 선택하거나 저장하지 않고 내장 패키지로 100% 자동 동작한다.

## T0104. VOD 분석 결과 카드 및 작업 목록 즉시 등록 [완료]

- **입력:** 사용자가 입력한 URL 문자열 (정상 치지직 VOD URL, 유효하지 않은 URL 등) 및 yt-dlp 분석 결과.
- **동작:**
  1. URL 유효성 검증 성공·실패 유무와 관계없이 다운로드 요청 시 메인 창의 작업 목록(`TaskListWidget`) 최상단(row 0)에 즉시 작업 카드(Task Card)를 추가하여, 새로 추가된 작업이 맨 위에 위치하고 오래된 항목이 아래로 배치되도록 한다.
  2. 유효하지 않은 URL인 경우:
     - 작업 카드가 빨간색으로 시각적 하이라이트된 실패 상태(`FAILED_INVALID`)로 추가된다.
     - 작업 카드의 1번 위치(좌상단)에 `Invalid: {입력 URL}`이 표시된다.
     - 토스트 알림에도 동일하게 `Invalid: {입력 URL}` 문구가 출력되며, 설정된 시간(2초) 후 자동으로 소멸된다.
  3. 유효한 치지직 VOD URL인 경우:
     - 작업 카드가 분석 진행 상태(`ANALYZING`)로 추가되고, 토스트 알림으로 `+ [URL]`(2초 자동 소멸)이 노출된다.
     - `yt-dlp` 비동기 분석 성공 시 작업 카드가 준비 완료 상태(`READY`)로 갱신되며, 1번 위치에 작업 표시명 규칙을 적용하여 갱신된다:
       - 라이브 시작일(`liveOpenDate`) 확인 시: `[{streamer}] {%Y-%m-%d} {title}`
       - 일반 VOD / 미확인 시: `[{streamer}] {title}`
     - 1번 위치 텍스트는 카드 너비를 초과할 경우 좌측 정렬 기준의 자동 줄바꿈(Word Wrap)이 적용되며, 마우스 진입 시 우측 상단 2번 위치 액션 아이콘이 노출되더라도 레이아웃이 요동치지 않도록 공간을 예약하여 일관된 줄바꿈을 유지한다.
     - VOD 분석 완료 시 썸네일 URL을 비동기로 로드하여 좌측 썸네일 영역(120×68px)에 이미지로 렌더링한다. 전체 재생 시간 및 기본 최고 화질이 함께 카드에 표시된다.
  4. VOD 분석 실패(인증 필요, 삭제/미존재 등)인 경우:
     - **인증(401 Unauthorized, 로그인/연령제한 등) 필요 시**: 작업 카드가 빨간색으로 하이라이트되며 1번 위치에 `Login required; Please login: {입력 URL}`이 표시된다. 4번 위치(좌하단)에 쿠키 설정 바로가기 및 로그인 연동 영역이 표시된다. 토스트 알림에도 동일 문구가 표시된 후 2초 뒤 자동 소멸된다.
     - **삭제/비공개/기타 오류 시**: 작업 카드가 빨간색으로 하이라이트되며 1번 위치에 `Invalid: {입력 URL}`(또는 상세 오류)이 표시되고, 토스트 알림에도 동일 문구가 표시된 후 2초 뒤 자동 소멸된다.
- **출력:** 작업 목록(`TaskListWidget`) 최상단에 썸네일과 시계 방향 4분면 레이아웃(1~4번 위치)을 갖춘 작업 카드가 추가·표시된다.
- **성공 기준:**
  - 새 작업 카드가 항상 작업 목록 가장 상단(Index 0)에 추가된다.
  - 1번 위치 작업 표시명이 `[{streamer}] {%Y-%m-%d} {title}` (라이브 확인 시) 또는 `[{streamer}] {title}` (일반) 형식으로 출력되며 긴 제목에 대해 좌측 정렬 줄바꿈이 정상 동작한다.
  - 마우스 진입(Hover) 시 2번 위치 액션 아이콘이 부드럽게 노출되며 줄바꿈 위치가 흔들리지 않는다.
  - VOD 분석 성공 시 썸네일 이미지가 좌측에 정상 로드·표시된다.
  - Naver Neonplayer Single-file DASH(KeyError sourceURL/media) 오류를 자체적으로 우회 처리하여 실제 치지직 VOD 메타데이터가 정상 추출된다.
  - 쿠키/로그인 필요(401 Unauthorized) VOD에 대해 `Login required; Please login: {입력 URL}` 상태 및 전용 UI가 올바르게 작동한다.

## T0105. VOD 분석 진행·취소·오류 및 중복 방지 (Merge Blocker & 중복 방지) [완료]

- **입력:** 분석 중 취소 버튼(✕), 동일 VOD URL 재입력 또는 네트워크·인증·삭제·비공개 오류.
- **동작:**
  1. **동일 영상 중복 방지 (옵션 A)**:
     - 작업 목록(`TaskListWidget`)에 이미 존재하는 동일한 VOD(파싱된 `video_no` 일치 또는 유효하지 않은 URL의 경우 동일 `raw_url`)가 재입력되면 중복 카드 생성을 차단한다.
     - 입력칸은 즉시 비우며, 안내 토스트로 `이미 추가한 작업입니다.`(2초 후 자동 소멸)를 표시한다.
  2. **분석 취소 및 늦은 결과 방어 (Merge Blocker)**:
     - 분석 중(`ANALYZING`) 카드의 2번 위치 삭제 버튼(✕) 클릭 시 해당 카드를 작업 목록에서 즉시 제거하고 비동기 스레드를 안전하게 정리한다.
     - 카드가 삭제된 후 뒤늦게 도착한 백그라운드 워커(`VodCheckWorker`) 또는 썸네일 다운로더(`ThumbnailLoaderThread`)의 콜백은 삭제된 Qt C++ 객체를 참조하지 않고 안전하게 무시(`sip.isdeleted` 및 카드 유효성 확인)하여 `RuntimeError: wrapped C/C++ object of type QLabel has been deleted` 크래시를 원천 방지한다.
     - 취소되거나 삭제된 카드가 화면에 다시 생성되거나 UI를 덮어쓰지 않는다.
- **출력:**
  - 중복 입력 시: `이미 추가한 작업입니다.` 빨간색/오류 오버레이 토스트 (2초 자동 소멸).
  - 카드 삭제 시: 해당 카드가 목록에서 즉시 제거되며, 목록이 비면 `작업 없음` 안내가 표시된다.
- **성공 기준:**
  - 동일한 치지직 VOD URL 또는 잘못된 URL을 연속으로 입력할 때 카드가 중복 생성되지 않고 `이미 추가한 작업입니다.` 토스트가 출력된다.
  - VOD 분석 도중 카드를 삭제하더라도 worker 응답 도착 시 크래시 없이 앱이 정상 구동을 유지한다.
  - 썸네일 로딩 중 카드가 삭제되어도 오류 없이 무시된다.

## T0106. 쿠키 파일·문자열 등록 및 브라우저 로그인 [완료]

- **입력:**
  - 작업 카드의 4번 위치 버튼: `[쿠키 설정]`(`cookie_btn`) 및 `[네이버 로그인]`(`login_btn`).
  - 상단 설정 버튼(`settings_btn`).
  - Netscape 쿠키 파일(`*.txt`), 직접 입력한 쿠키 문자열(Netscape 탭 구분 텍스트 또는 HTTP Raw Header `NID_AUT=...; NID_SES=...`), 내장 웹브라우저 네이버 로그인 성공 이벤트.
- **동작:**
  1. **작업 카드 4번 위치 액션 분리**:
     - `[쿠키 설정]`: 메인 창과 동시 조작 가능한 Modeless 설정 창(`SettingsWindow`)을 호출하여 쿠키 파일 불러오기, 직접 입력, 내보내기, 초기화 등의 관리 작업을 수행한다.
     - `[네이버 로그인]`: 내장 웹브라우저(`QWebEngineView`) 기반의 네이버 로그인 다이얼로그(`NaverLoginDialog`)를 직접 호출한다.
  2. **내장 웹브라우저 네이버 로그인 다이얼로그 (`NaverLoginDialog`)**:
     - 안정적인 세션 유지를 위해 전역 기본 프로필(`QWebEngineProfile.defaultProfile()`)에서 네이버 로그인 페이지(`https://nid.naver.com/nidlogin.login?url=https%3A%2F%2Fchzzk.naver.com`)를 로드한다.
     - 사용자가 브라우저 창에서 ID/PW, QR 코드, 2단계 인증 등을 진행하면 `QWebEngineCookieStore`가 `.naver.com` 도메인의 `NID_AUT` 및 `NID_SES` 쿠키를 실시간으로 감지한다.
     - 로그인 완료(치지직/네이버 메인 리디렉트 감지 또는 사용자의 '로그인 완료' 버튼 클릭) 시 감지된 세션 쿠키를 Netscape 포맷으로 자동 변환하여 로컬 파일(`~/.chzzk_downloader/cookies.txt`)에 저장하고 창을 닫는다.
  3. **Modeless 설정 창 (`SettingsWindow`)**:
     - 메인 창 조작을 차단하지 않는 Non-modal 윈도우(`setModal(False)`)로 실행된다.
     - **보안 원칙**: 설정 창 메인 UI에는 쿠키 원문 시크릿 값을 평문 노출하지 않고 요약 상태(`쿠키 등록됨 (N개 항목)` 또는 `등록된 쿠키 없음`)만 표시한다.
     - 직관적인 5대 단일 버튼 구성 (하위 드롭다운 메뉴 제거):
       - `[네이버 로그인]`: 내장 브라우저 로그인 창(`NaverLoginDialog`) 호출 (녹색 강조).
       - `[보기 / 직접 입력]`: F12 개발자 도구 복사 경로 안내 및 실시간 유효성 검증 기능이 포함된 모달 쿠키 뷰어(`CookieViewerDialog`) 호출.
       - `[파일 불러오기]`: Netscape 쿠키 파일(`*.txt`) 선택 다이얼로그 즉시 실행. (※ Chrome 127+ App-Bound Encryption issue 10927 영구 차단으로 인해 외부 브라우저 직접 추출은 배제하고 내장 로그인 및 파일 불러오기로 일원화)
       - `[내보내기]`: 저장된 쿠키를 `cookies.txt` 파일로 저장.
       - `[초기화]`: 확인 대화상자 후 저장된 쿠키 파일 삭제 및 상태 초기화.
  4. **옵션 A (쿠키 등록/갱신 시 자동 재분석 트리거)**:
     - 내장 네이버 로그인 성공, 파일 불러오기, 직접 입력 저장으로 쿠키가 등록되거나 갱신되면 작업 목록(`TaskListWidget`)의 모든 `FAILED_LOGIN_REQUIRED` 카드를 즉시 `ANALYZING` 상태로 전환하고 백그라운드 재분석(`VodCheckWorker`)을 자동 실행한다.
     - 재분석 중 QThread 가비지 컬렉션으로 인한 프로세스 비정상 종료를 방지하기 위해 강한 참조(`_recheck_workers`)를 유지한다.
  5. **yt-dlp VOD 분석 시 쿠키 자동 연동**:
     - 유효 쿠키 존재 시 `extract_vod_info()` 호출에 `cookiefile` 옵션을 자동으로 주입하여 성인 인증 및 회원 전용 VOD 메타데이터를 정상 추출한다.
- **출력:**
  - 설정 창 상태 라벨: `쿠키 등록됨 ({count}개 항목)` (녹색) 또는 `등록된 쿠키 없음` (회색).
  - 네이버 로그인 성공 시 `+ 네이버 로그인이 완료되었습니다.` 성공 토스트(2초 자동 소멸).
  - 작업 카드: 쿠키 갱신 시 `FAILED_LOGIN_REQUIRED` 카드가 `ANALYZING`을 거쳐 `READY` 상태(제목, 썸네일, 화질 정보 등)로 자동 복구.
- **성공 기준:**
  - `[네이버 로그인]` 버튼 클릭 시 설정 창 대신 실제 내장 네이버 로그인 창이 열리고, 로그인 완료 시 쿠키가 자동 추출·저장된다.
  - `[쿠키 설정]` 버튼 클릭 시 Modeless 설정 창이 정상 오픈되며, `[파일 불러오기]` 클릭 시 파일 선택창이 바로 열린다.
  - Netscape 텍스트 파일 및 `NID_AUT=...; NID_SES=...` 형태의 직접 입력 문자열 모두 오류 없이 Netscape 규격으로 변환 및 저장된다.
  - 쿠키 등록/갱신 즉시 기존의 로그인 필요 실패 카드가 자동으로 재분석되어 성공 상태로 복구된다(옵션 A).
  - 저장된 쿠키는 설정 창 메인 UI에 평문 노출되지 않아 보안을 유지한다.

## T0107. 앱 시작 시 쿠키 세션 검증 및 쿠키 삭제 [완료]

- **입력:**
  - 앱 기동(GUI 시작) 이벤트 및 저장된 로컬 쿠키 파일(`~/.chzzk_downloader/cookies.txt`).
  - 환경 설정 창의 `[초기화]`(쿠키 삭제) 버튼 클릭.
  - 만료 알림 토스트 내 `[쿠키 설정]`, `[네이버 로그인]`, `[닫기(✕)]` 버튼 클릭.
- **동작:**
  1. **앱 기동 시 백그라운드 1회 세션 검증**:
     - 앱 시작 시 저장된 쿠키 파일이 존재하면 백그라운드 비동기 워커(`CookieVerifyWorker`)를 실행하여 치지직/네이버 유저 상태 API(`GET https://comm-api.game.naver.com/nng_main/v1/user/getUserStatus`, 타임아웃 3초)로 세션 유효성을 1회 확인한다.
     - 메인 창 UI 프리징이나 블로킹 없이 조용히 비동기 처리한다.
  2. **상태 판별 및 피드백 규칙 (정상 시 정숙, 문제 시 즉시 조치 액션 제공)**:
     - **인증 정상 (200 OK & loggedIn: true)**:
       - 팝업이나 토스트 없이 정숙(침묵)을 유지한다.
       - 설정 창의 쿠키 상태 라벨에 사용자 닉네임과 최근 확인 시각을 조용히 반영한다 (예: `쿠키 등록됨 (사용자닉네임 · 최근 확인: 15:30)`).
     - **세션 만료 (401 Unauthorized 또는 loggedIn: false / 로그아웃 등)**:
       - 설정 창 상태 라벨을 `쿠키 만료됨 (재로그인 필요)` (주황/빨간색)으로 표시한다.
       - 메인 창 상단에 **액션 버튼이 포함된 인터랙티브 토스트(Action Toast)**를 노출한다:
         - 구성: `[경고 아이콘] 저장된 네이버 쿠키가 만료되었습니다.` 안내 문구와 우측 `[쿠키 설정]` | `[네이버 로그인]` | `[✕]` 순서 배치.
         - 사용자가 조작하기 전까지 자동 소멸되지 않고 유지된다.
         - `[쿠키 설정]` 클릭 시: Modeless 설정 창(`SettingsWindow`)을 호출하고 토스트를 닫는다.
         - `[네이버 로그인]` 클릭 시: 즉시 내장 브라우저 로그인 창(`NaverLoginDialog`)을 호출하고 토스트를 닫는다 (로그인 완료 시 세션 자동 갱신).
         - `[✕]` 클릭 시: 토스트를 닫는다.
     - **네트워크 오류 / 잘못된 형식**:
       - 오프라인이거나 일시적 네트워크 장애 시 기존 쿠키를 임의로 삭제하지 않고 설정 창 라벨에 `네트워크 연결 실패 (확인 불가)` 등으로 표시한다.
     - **쿠키 없음**:
       - 검증 요청을 생략하고 기존대로 `등록된 쿠키 없음`을 유지한다.
  3. **앱 구동 중 세션 판별**:
     - 별도의 수동 확인 버튼을 두지 않으며, 구동 중에는 VOD 분석 시 401 오류가 반환되면 기존 T0104/T0105 규칙에 따라 자연스럽게 작업 카드가 `Login required; Please login: ...` 상태로 처리되고 4번 위치에 `[쿠키 설정]`, `[네이버 로그인]` 버튼이 제공된다.
  4. **쿠키 삭제 (`[초기화]`)**:
     - 설정 창의 `[초기화]` 버튼 클릭 시 확인 대화상자를 거쳐 로컬 `cookies.txt` 파일을 영구 삭제하고 설정 창 상태를 `등록된 쿠키 없음`으로 즉시 갱신한다.
     - 기존 작업 목록에 이미 추가되어 분석 완료된 카드는 상태를 강등하거나 훼손하지 않고 그대로 유지한다.
     - 쿠키 삭제 이후 새로 추가되거나 재분석되는 인증 필요 VOD에 대해서는 쿠키가 없으므로 정상적으로 `Login required; Please login: ...` 상태로 처리된다.
- **출력:**
  - 정상 시: 침묵 유지, 설정 창 라벨에 최근 확인 시각 표시.
  - 만료 시: `[쿠키 설정] [네이버 로그인]` 액션 버튼이 포함된 만료 경고 오버레이 토스트 및 설정 창 `쿠키 만료됨` 라벨.
  - 삭제 시: `쿠키가 초기화되었습니다.` 안내 메시지 및 설정 창 `등록된 쿠키 없음` 라벨.
- **성공 기준:**
  - 앱 시작 시 유효한 쿠키가 있으면 백그라운드로 1회 검증되어 정상 유지되고 별도 팝업/토스트가 뜨지 않는다.
  - 만료된 쿠키인 경우 앱 시작 시 `[쿠키 설정] [네이버 로그인] [✕]` 액션 버튼이 포함된 경고 토스트가 표시된다.
  - 토스트 내 `[쿠키 설정]` 클릭 시 설정 창이 열리고, `[네이버 로그인]` 클릭 시 내장 로그인 창이 열려 즉시 갱신이 가능하다.
   - 쿠키 삭제 시 로컬 파일이 제거되고, 기존 작업 카드는 온전히 유지되며, 이후 추가되는 인증 필요 영상은 `Login required`로 정확히 처리된다.

## T0108. 기본 다운로드 설정 [완료]

- **입력:**
  - 저장 폴더 경로 (`Path` / `str`)
  - 기본 다운로드 화질 (`str`, 예: `최고 화질`, `1080p`, `720p`, `480p`, `360p`)
  - 기본 파일 확장자 (`str`, `.mp4` 또는 `.ts`)

  1. **설정 영속화 관리 (`settings_manager.py` / `config.py`)**:
     - 설정 파일 경로: `~/.chzzk_downloader/settings.json` (기존 쿠키 파일과 동일한 디렉터리 내 JSON 포맷으로 보관)
     - 파일 미존재 또는 파일 손상 시 기본값으로 안전하게 자동 복구
     - **초기 기본값**:
       - 저장 폴더: 애플리케이션 실행/GUI가 속한 폴더 하위 `chzzk_downloaded` (앱 실행 시 자동 생성)
       - 기본 화질: `최고 화질` (Best)
       - 기본 파일 확장자: `.mp4`
     - **원자적 저장(Atomic Write) 적용**: 파일 쓰기 도중 강제 종료되어도 0바이트/손상 파일이 남지 않도록 임시 파일(`settings.json.{uuid}.tmp`) 경유 교체.
  2. **환경설정 창 UI (`SettingsWindow`) 레이아웃 구성**:
     - **배치 순서**: 설정 창 진입 시 **쿠키 설정보다 위쪽**에 **"일반"** 그룹 (`QGroupBox("일반")`)을 배치한다.
     - **저장 폴더 UI**:
       - "저장 폴더" 라벨 아래에 현재 설정된 폴더명/경로 표시창(`QLineEdit`, 읽기 전용)과 경로 설정용 **폴더 아이콘 버튼**을 배치한다.
       - 직접 텍스트 입력을 허용하지 않으며, 폴더 아이콘 클릭 시 시스템 디렉터리 선택 창(`QFileDialog.getExistingDirectory`)을 통해서만 경로를 지정할 수 있다.
     - **화질 (품질) Dropdown**:
       - `QComboBox` 드롭다운 형태로 구현 (`최고 화질`, `1080p`, `720p`, `480p`, `360p`).
       - 기본 선택값: `최고 화질`.
     - **파일 확장자 Dropdown**:
       - `QComboBox` 드롭다운 형태로 구현 (`.mp4`, `.ts`).
       - 기본 선택값: `.mp4`.
  3. **폴더 유효성 및 쓰기 권한 검증**:
     - 사용자가 탐색기에서 폴더를 선택하면 실제 경로 존재 여부 및 임시 파일 쓰기/삭제 테스트를 통해 쓰기 권한을 즉시 검증한다.
     - 쓰기 권한이 없거나 유효하지 않은 폴더인 경우: 경고 팝업(`QMessageBox.warning`)을 표시하고 이전 정상 경로를 그대로 유지한다.
  4. **자동 저장 및 전역 설정 연동**:

     - 전역 설정 인터페이스(`get_settings()`, `save_settings()`)를 제공하여 후속 티켓(T0109, T0111 등)에서 기본값으로 즉시 참조할 수 있도록 한다.
- **출력:**
  - 설정 창 상단 "일반" 그룹 내 저장 폴더(읽기 전용 경로 + 폴더 아이콘), 화질 드롭다운, 확장자 드롭다운 표시.

- **성공 기준:**
  - 앱 초기 기동 시 GUI 하위 `chzzk_downloaded` 폴더가 자동 생성되고 기본 저장 폴더로 등록된다.
  - 텍스트 직접 입력 없이 폴더 아이콘을 통한 탐색기 선택으로만 경로가 안전하게 지정된다.
  - 쓰기 권한이 없는 폴더는 저장이 거부되고 경고가 표시되며 이전 유효 경로가 유지된다.
  - 화질 및 확장자가 Dropdown으로 정상 선택되고, 앱 재실행 후에도 저장된 설정값(저장 폴더, 화질, 확장자)이 정확히 복원된다.

## T0109. VOD 다운로드 설정 및 진입 제어 [완료]

- **입력:**
  - 환경설정(`SettingsWindow > 일반`)의 `VOD 자동 다운로드` 토글 스위치 (기본값: ON)
  - VOD 작업 카드 분석 완료 메타데이터 (`VodInfo`: 최고화질, formats 목록, duration, 제목 등)
  - 4번 위치의 개별 제어: 화질 드롭다운 선택, 확장자 드롭다운(`.mp4`/`.ts`) 선택, 폴더 아이콘(`📁`) 클릭, 다운로드 시작 아이콘(`▶`) 클릭, 녹화 중지 아이콘(`■`) 클릭
- **동작:**
  1. **분석 중 안내 문구 형식 변경**:
     - VOD URL 입력 즉시 1번 위치 문구를 기존 `분석 중... (URL)`에서 `읽는 중… {URL}` 형식으로 표시한다.
  2. **환경설정 토글 스위치 위젯 구현**:
     - `SettingsWindow` 일반 그룹에 `VOD 자동 다운로드` 스위치(클릭 시 회색 ↔ 파란색 전환 및 원이 좌우 이동) 추가 (기본 ON).
     - `settings.json`에 `vod_auto_download` 필드로 영속화.
  3. **VOD 화질 및 확장자 설정 연동과 자동 다운로드 분기**:
     - **설정 기본값 우선 반영**:
       - 영상 분석 완료 시, 환경설정에서 지정한 **기본 화질**(`default_quality`: `최고 화질`, `1080p`, `720p`, `480p`, `360p`)과 **기본 확장자**(`file_extension`: `.mp4`, `.ts`)를 해당 카드의 기본값으로 자동 매칭하여 적용한다.
       - **3번 위치 (우하단)**: 설정에서 지정된 기본 화질 및 재생시간(`{quality} | {duration}`)을 표시한다.
     - **`ON`**: 분석 완료(`READY`) 즉시 파일 중복 검사 후 설정의 기본 화질 및 기본 확장자로 다운로드 상태로 자동 진입.
     - **`OFF`**: 4번 위치(좌하단)에 `[기본 화질 드롭다운] [기본 확장자 드롭다운 (.mp4/.ts)]` + `[📁]` + `[▶]`를 표시하고 대기.
       - **화질 드롭다운**: 설정에서 지정한 기본 화질이 우선해서 기본 선택되어 나타나며, 클릭 시 드롭다운에는 해당 영상에서 제공 가능한 모든 실제 화질 목록(예: 1080p60, 720p, 480p...)이 제시되어 자유롭게 변경할 수 있다. 변경 시 3번 위치(우하단)의 화질 표시(`{quality} | {duration}`)도 실시간 동기화된다.
       - **확장자 드롭다운**: 설정에서 지정한 확장자(`.mp4` 또는 `.ts`)가 기본으로 선택되며, 클릭 시 다른 확장자로 변경할 수 있다.
       - 폴더 아이콘(`📁`): 클릭 시 탐색기를 열어 이 카드의 저장 폴더를 개별 변경.
       - 시작 아이콘(`▶`): 클릭 시 파일 중복 검사 후 최종 선택된 화질/확장자로 다운로드 시작.
  4. **기존 파일명 중복(충돌) 처리 (옵션 A)**:
     - 저장 폴더에 동일한 파일명이 이미 존재할 경우 대화상자를 표시하여 `[덮어쓰기]`, `[이름 변경 (1) 추가]`, `[취소]` 중 선택한다.
  5. **다운로드 실행 상태 UI 전환 및 중지(완결) 안전장치**:
     - 다운로드 시작 시 4번 위치의 설정 아이콘들이 사라지고 `녹화 중…` + 버퍼링(회전 표시) + `■` (빨간색 중지 버튼)으로 변경된다.
     - `■` 버튼 호버 시: 짙은 회색 라운드 사각형이 둘러지며 진하게 하이라이트된다.
     - `■` 버튼 클릭 시: `정말 중지하시겠습니까?` (확인 / 취소, '확인' 버튼 기본 하이라이트) 확인 모달을 띄우고, '확인' 선택 시 다운로드를 안전하게 중단하고 완결된 작업(`STOPPED`)으로 처리한다.
     - **중지 후 재개 불가 완결 상태 보장**: 다운로드가 일단 중지되면 결손/중복 프레임 방지를 위해 이어서 재개할 수 없으므로, 4번 위치에 화질, 확장자, 폴더, 시작 아이콘이 일체 나타나지 않고 깔끔하게 숨겨진다.
  6. **동일 VOD 재다운로드 및 상태별 중복/연속 입력 방어**:
     - **진행 중 / 대기 중 상태의 동일 URL 즉시 거부**:
       - 읽는 중(`ANALYZING`), 녹화 중(`DOWNLOADING`), 대기 중(`READY`) 상태인 작업에 대해 동일 URL이 입력된 경우, 확인 모달 없이 즉시 `이미 추가한 작업입니다.` 에러 토스트를 노출하고 URL 입력칸을 비우며 새 작업 생성을 원천 차단한다.
       - 동일 URL이 아주 짧은 시간 간격(밀리초 단위의 연타/더블클릭)으로 연속 입력되는 경우에도 동기적 카드 등록 및 검증을 통해 단 1장의 작업 카드만 유지하며 중복 생성을 안전하게 방어한다.
     - **완결(중지/완료/실패) 작업의 재다운로드 확인 및 클린 리셋**:
       - 작업 목록에 중지(`STOPPED`) 또는 완료된 VOD 카드가 남아있는 상태에서 동일 URL을 재입력할 경우, `이미 추가된 작업입니다. 다시 다운로드하시겠습니까?` (확인 / 취소, '확인' 버튼 기본 하이라이트) 모달을 노출한다.
       - **'확인' 선택 시 처리**: 이전 세션의 잔여 스레드/워커 및 파일 핸들을 완전히 정리(clean teardown)하고, 기존 카드를 클린 리셋(Clean Reset)하여 이전 상태 플래그와의 충돌 없이 온전한 새 다운로드를 처음부터 실행한다. 이때 이전 작업 세션의 화질/확장자/폴더 잔여값을 버리고, 현재 시점의 최신 환경설정(기본 화질, 기본 확장자, 기본 저장 폴더)을 최우선으로 반영한다.
       - **'취소' 선택 시 처리**: 기존 목록의 완결 카드를 보존하고 URL 입력창만 비운다.
- **출력:**
  - 설정 창의 토글 스위치 위젯.
  - 카드의 1번 위치 `읽는 중… {URL}` 표시.
  - 카드의 3번 위치 기본/선택 화질 및 재생시간 표시.
  - 카드의 4번 위치 화질/확장자 드롭다운, 폴더/시작/중지 인터랙션 위젯, 파일 중복 대화상자, 중지 확인 대화상자, 상태별 동일 작업 거부 토스트 및 재다운로드 확인 모달.
- **성공 기준:**
  - 설정에서 지정한 기본 화질로 3번 위치에 정상 표시되고, 자동 다운로드 시 해당 화질 및 확장자로 다운로드된다.
  - 자동 다운로드 OFF 시 4번 위치에 설정의 기본 화질 및 확장자가 우선 선택되어 나타나며, 클릭 시 영상에서 제공 가능한 모든 실제 화질 목록이 제공된다.
  - 4번 위치에서 화질 변경 시 3번 위치의 화질 표시가 실시간 동기화된다.
  - 동일 파일명 존재 시 덮어쓰기/이름변경/취소 선택 분기가 정상 동작한다.
  - 다운로드 시작 시 `녹화 중… 버퍼링 ■`으로 UI가 정확히 전환된다.
  - 중지 버튼 호버 스타일 및 확인/취소 모달이 정상 동작하며, '확인' 버튼에 기본 하이라이트가 적용되고 중지 완료 후 4번 위치의 컨트롤이 모두 숨겨진다.
  - 읽는 중/대기 중/녹화 중 동일 URL 입력 및 아주 짧은 간격의 연속 입력 시 모달 없이 즉시 토스트로 거부되고 중복 카드가 생성되지 않는다.
  - 중지/완료된 VOD 카드가 남아있는 상태에서 동일 URL 재입력 시 확인/취소 모달('확인' 버튼 기본 하이라이트)을 거쳐 클린 리셋 후 최신 환경설정(기본 화질/확장자)을 반영하여 정상 재다운로드된다.

## S01.3 사용자는 분석한 VOD를 원하는 품질로 다운로드한다

### T0110. FFmpeg 상태 확인 및 호환성 검증

- **입력:** 저장된 FFmpeg 경로 또는 기본 실행 위치.
- **동작:**
  1. FFmpeg 바이너리 실행 가능 여부와 버전 문자열(`ffmpeg -version`)을 파싱하여 확인하고, 없으면 파일 선택 다이얼로그로 경로를 지정할 수 있게 한다.
  2. **최신 FFmpeg(v6.1+ 및 2024~2026 나이틀리 빌드) HLS `.m4v` 호환성 방어 검증**:
     - 최신 FFmpeg에서 CVE 보안 취약점 방지를 위해 HLS demuxer의 확장자 엄격 검사(`extension_picky`)가 기본 활성화됨에 따라, 치지직의 fMP4 `.m4v` 세그먼트가 `mismatches allowed extensions in url` 에러로 차단(`Invalid data found when processing input`)되는 문제를 사전 방지한다.
     - 설치된 FFmpeg가 `-extension_picky 0` 및 `-allowed_extensions ALL` 인자를 지원하는지 확인하고, 향후 VOD 다운로드(T0111) 및 라이브 녹화(T0206) 호출 시 전역 기본 인자로 자동 주입되도록 구성한다.
- **출력:** `사용 가능` (버전 정보 및 치지직 호환 인자 검증 완료), `파일 없음`, `실행 실패`, `응답 없음`, 경로·버전과 `실행 파일 선택` 버튼이 표시된다.
- **성공 기준:** FFmpeg가 필요한 VOD/녹화 작업은 사용할 수 없을 때 시작하지 않는다. 실제 FFmpeg만 저장할 수 있고, 최신 나이틀리 빌드 환경에서도 치지직 호환 인자가 정상 인식되어 다운로드를 계속할 수 있다.

### T0111. 다운로드 작업 생성

- **입력:** VOD URL, 제목, 선택 품질, 저장 폴더, 예상 파일명과 다운로드 시작 버튼.
- **동작:**
  1. VOD 작업을 생성해 작업 목록에 추가하고 yt-dlp 공식 Python API로 다운로드를 시작한다.
  2. **최신 FFmpeg `.m4v` 확장자 거부 및 네이버 CDN 400 Bad Request 방어 옵션 주입**:
     - 치지직 fMP4 세그먼트(`.m4v`) 처리 시 최신 FFmpeg가 `mismatches allowed extensions in url` 에러로 종료되지 않도록 yt-dlp 옵션에 `postprocessor_args: ["-extension_picky", "0", "-allowed_extensions", "ALL"]` 및 필요 시 `--downloader-args "ffmpeg:-extension_picky 0 -allowed_extensions ALL"`를 자동 주입한다.
     - 네이버 CDN(`nvelop-livecloud.pstatic.net`) 요청 시 400 Bad Request 방지를 위해 `http_headers`에 `Referer: https://chzzk.naver.com/` 및 `User-Agent`를 명시적으로 주입한다.
  3. 작업 표시명 및 저장 파일명 규칙을 적용한다:
     - 기본 VOD: `[{streamer}] {title} ({videoNo})`
     - 라이브 시작일(`liveOpenDate` 등) 확인 시: `[{streamer}] date:{%Y-%m-%d}; {title} ({videoNo})`
     - Windows 파일명 호환을 위해 파일명 내 콜론(`:`)은 전각 콜론(`：`)을 사용한다.
  4. 작업 목록 항목(Row)의 시계 방향 4분면 레이아웃(1~4번 위치) 및 인터랙션을 구성한다:
     - **1번 위치 (좌상단)**: 작업 표시명 (실패/인증 필요 시 `Invalid` 또는 `Login required; Please login: {입력 URL}`)
     - **2번 위치 (우상단)**: 회색조 액션 아이콘 그룹
       - 아이콘 구성: `폴더 열기`, `파일 삭제`, `순서 변경`(클릭 유지 상태로 드래그하여 목록 순서 변경), `다시 시작`, `목록에서 제거`
       - 다운로드 시작이 실패하여 파일/폴더가 존재하지 않는 경우 `폴더 열기`와 `파일 삭제` 아이콘은 표시하지 않는다.
       - 평소에는 숨겨져 있다가 마우스가 특정 영상 행에 진입(Row Hover) 시 회색조로 노출된다.
       - 아이콘 Hover 시: 아이콘 색상이 검은색으로 변경되고 사각형 하이라이트 박스(단, `파일 삭제`는 빨간색 하이라이트)가 적용되며, 해당 기능 툴팁이 프로그램 위에 오버레이된다.
     - **3번 위치 (우하단)**: 진행 상태 표시 항목 (진행률 %, 경과 시간, 현재 다운로드 용량 / 전체 용량, 속도)
     - **4번 위치 (좌하단)**: 쿠키/인증 필요 시 `쿠키 설정 바로가기 아이콘`, `내장 웹브라우저 네이버 로그인 창 호출 아이콘` 노출
     - **행 인터랙션**: 마우스 진입(Hover) 시 회색빛 하이라이트, 마우스 클릭 시 진한 색상으로 하이라이트된다.
- **출력:** 작업 목록에 4분면 레이아웃으로 구성된 작업 카드가 추가되고 `대기/실행 중` 상태와 작업 정보가 표시된다.
- **성공 기준:** 시작 버튼 한 번에 작업 하나만 생성된다. 명명 규칙과 전각 콜론이 정상 적용된다. 최신 FFmpeg 환경에서도 `.m4v` 세그먼트 거부 없이 다운로드가 정상 진행된다. 마우스 Hover 및 Click 시 지정된 하이라이트 및 아이콘/툴팁 오버레이가 정상 동작한다. 동일 URL·품질·저장 경로의 진행 작업이 있으면 새 작업 대신 기존 작업을 안내한다.

### T0112. 다운로드 진행률과 완료

- **입력:** yt-dlp Python API의 진행 정보와 종료 결과.
- **동작:** 받은 용량, 전체 용량, 진행률, 속도, 현재 다운로드 진행 시간(경과 시간)을 실시간 갱신하여 3번 위치에 반영하고, 종료 후 결과 파일을 확인한다.
- **출력:** 3번 위치에 진행 막대, 진행률(%), 다운로드 속도, 진행 경과 시간, 현재 용량 / 전체 용량이 실시간 표시되고, 성공 시 `완료`와 최종 파일 크기가 표시되며 2번 위치의 `폴더 열기` 및 `파일 삭제` 아이콘이 활성화된다.
- **성공 기준:** 일부 진행값을 읽지 못해도 작업은 계속된다. 외부 도구 정상 종료와 결과 파일 존재·크기 0 초과를 모두 확인한 뒤 완료로 표시한다. 파일 생성 완료 후 폴더 열기 및 파일 삭제 아이콘이 정상 동작한다.

### T0113. VOD 취소와 실패 재시도

- **입력:** 실행 작업의 취소 또는 실패·취소 작업의 재시도 버튼.
- **동작:** 취소 시 해당 외부 작업을 종료하고 재시도 시 기존 옵션으로 새 작업을 만든다.
- **출력:** 원 작업에는 `취소/실패`, 종료 시각·이유가 남고 재시도 작업은 새 작업 ID로 추가된다.
- **성공 기준:** 취소 후 파일 크기가 더 증가하지 않는다. 재시도가 원 작업 기록을 덮어쓰지 않는다. 인증·설정 수정이 필요한 실패는 수정 전 자동 반복하지 않는다.

# E02. 현재 라이브 방송을 수동 녹화

이 Epic이 끝나면 기존 앱에서 채널·라이브 URL을 분석하고 현재 방송을 시작·중지해 재생 가능한 파일을 얻을 수 있다.

## S02.1 사용자는 채널·라이브 URL에서 현재 방송을 확인한다

### T0201. 채널·라이브 URL 판별 추가

- **입력:** URL 입력 문자열.
- **동작:** 기존 VOD 판별에 채널 URL과 라이브 URL 판별을 추가하고 채널 ID를 추출한다.
- **출력:** 분석 중 결과 영역에 `채널 정보 확인 중` 또는 `라이브 상태 확인 중`이 표시된다.
- **성공 기준:** URL 분석은 조회만 수행한다. 분석만으로 녹화나 채널 등록이 시작되지 않는다.

### T0202. 오프라인 채널 결과

- **입력:** 채널 정보와 현재 오프라인 상태.
- **동작:** 오프라인 채널 결과 카드를 표시한다.
- **출력:** 프로필, 채널명, 팔로워 수, 상태 `오프라인`, 마지막 확인 시각이 표시된다.
- **성공 기준:** 이전 방송 제목·카테고리·시청자를 현재 정보처럼 표시하지 않는다. 녹화 시작 버튼은 표시하지 않는다.

### T0203. 라이브 방송 결과

- **입력:** 채널 정보와 현재 라이브 정보·품질 목록.
- **동작:** 현재 방송 카드를 표시한다.
- **출력:** 방송 썸네일·제목, 채널명, 카테고리, 태그, 시청자 수, 팔로워 수, 시작 시각, 품질 목록과 `녹화 설정` 버튼이 표시된다.
- **성공 기준:** 현재 방송값과 화면값이 일치한다. 정보가 없는 항목은 `확인 불가`로 표시한다. 녹화 설정 버튼을 누르기 전에는 작업이 생성되지 않는다.

### T0204. Streamlink 상태 확인

- **입력:** 저장된 Streamlink 경로 또는 기본 실행 위치.
- **동작:** Streamlink 실행 가능 여부와 버전을 확인하고 없으면 파일 선택으로 경로를 지정할 수 있게 한다.
- **출력:** 도구 상태·경로·버전, 녹화 가능 여부와 `실행 파일 선택`이 표시된다.
- **성공 기준:** 실제 Streamlink만 저장할 수 있다. 필요한 도구가 없으면 녹화를 시작하지 않고 정상 경로 선택 후 다시 진행할 수 있다.

## S02.2 사용자는 라이브 녹화를 시작하고 중지한다

### T0205. 녹화 설정 확인

- **입력:** 라이브 카드의 녹화 설정 버튼, 품질 목록, 저장 폴더.
- **동작:** 품질, 확장자, 예상 파일명(`[{streamer}] date:{%Y-%m-%d %H：%M}; {title}`, 전각 콜론 사용)과 저장 위치를 확인하는 화면을 연다.
- **출력:** 실제 제공 품질, 결과 확장자, 최종 경로와 `녹화 시작`, `취소`가 표시된다.
- **성공 기준:** 사용할 수 없는 품질·확장자는 시작 전에 안내된다. 화면을 여는 것만으로 녹화하지 않는다.

### T0206. 최신 상태 확인 후 녹화 시작

- **입력:** 녹화 시작 버튼, 채널 ID, 선택 품질·확장자·경로.
- **동작:**
  1. 최신 라이브·방송 ID를 다시 확인하고 방송 중이면 Streamlink 또는 FFmpeg 프로세스를 실행한다.
  2. **최신 FFmpeg(v6.1+) 치지직 HLS `.m4v` 세그먼트 거부 및 CDN 400 Bad Request 방어**:
     - 치지직 라이브 HLS 스트림은 세그먼트로 `.m4v`를 사용하므로, FFmpeg 직접 실행 시 입력(`-i`) 앞단에 `-extension_picky 0` 및 `-allowed_extensions ALL` (또는 `-allowed_segment_extensions ALL`) 옵션을 필수로 전달하여 `mismatches allowed extensions in url`로 인한 `Invalid data found when processing input` 에러(exit code 1)를 원천 방지한다.
     - 네이버 라이브 클라우드(`nvelop-livecloud.pstatic.net`)의 400 Bad Request 방지를 위해 `-headers "Referer: https://chzzk.naver.com/\r\nUser-Agent: ...\r\n"`를 명시적으로 전달한다.
     - Streamlink를 통한 녹화 시에도 동일하게 치지직 전용 헤더 및 FFmpeg 패스스루 인자(`--ffmpeg-ffmpeg-args "extension_picky=0:allowed_extensions=ALL"`)가 적용되도록 보장한다.
  3. 작업 표시명 및 저장 파일명에 `[{streamer}] date:{%Y-%m-%d %H：%M}; {title}`(전각 콜론 사용)을 적용하고 T0111의 4분면 작업 카드 레이아웃을 사용한다.
- **출력:** 작업 목록 1번에 라이브 작업명, 3번에 진행 경과 시간, 수신 용량, 다운로드 속도 및 `녹화 중` 상태가 실시간 표시된다.
- **성공 기준:** 오프라인이면 프로세스를 만들지 않는다. 최신 FFmpeg 나이틀리 자동 갱신 환경에서도 `.m4v` 세그먼트 차단 없이 첫 미디어 데이터가 들어온 뒤 녹화 중으로 표시되고 파일 크기가 지속 증가한다. 전각 콜론이 정상 적용된다.

### T0207. 같은 방송 중복 녹화 방지

- **입력:** 새 녹화 요청의 채널 ID·방송 ID와 현재 녹화 작업.
- **동작:** 같은 방송 ID의 진행 작업을 찾고 있으면 새 프로세스를 시작하지 않는다.
- **출력:** 기존 작업 ID, 시작 시각과 상태가 안내되고 기존 작업 행이 선택된다.
- **성공 기준:** URL 화면과 작업 재시도에서 요청이 겹쳐도 같은 방송의 녹화 프로세스는 하나다.

### T0208. 녹화 중지와 파일 확인

- **입력:** 녹화 작업의 중지 버튼.
- **동작:** 외부 프로그램에 정상 종료를 요청하고 파일의 재생 시간·영상·음성을 확인한다.
- **출력:** 정상 파일은 `완료`와 경로·길이가 표시되고 강제 종료·마감 실패 파일은 `중단됨`과 이유가 표시된다.
- **성공 기준:** 정상 완료 파일은 재생 가능하다. 중지 버튼 반복이 상태를 여러 번 변경하지 않는다. 강제 종료 파일을 정상 완료로 표시하지 않는다.

### T0209. 작업 기록 재실행 복원

- **입력:** VOD·녹화 작업 상태와 앱 시작.
- **동작:** 완료·취소·실패·중단 작업을 저장하고 재실행 시 작업 목록에 복원한다.
- **출력:** 이전 작업의 종류, 대상, 마지막 상태, 시각, 경로와 실패 이유가 표시된다.
- **성공 기준:** 앱을 다시 실행해도 기록을 확인할 수 있다. 실제 프로세스가 없는 실행 중 작업은 `이전 실행에서 중단됨`으로 표시된다.

# E03. 관심 채널을 등록하고 수동 관리

이 Epic이 끝나면 사용자는 분석 결과에서 채널을 명시적으로 등록하고 재실행 후에도 목록에서 상태를 새로고침·검색·녹화할 수 있다.

## S03.1 사용자는 분석한 채널을 등록한다

### T0301. 채널 등록 버튼과 개념

- **입력:** 채널 또는 라이브 분석 성공 결과.
- **동작:** 결과 카드에 `채널 등록` 버튼을 추가한다. URL 분석 자체는 목록을 변경하지 않는다.
- **출력:** 미등록 채널에는 `채널 등록`, 등록 채널에는 `이미 등록됨`과 `등록 채널 보기`가 표시된다.
- **성공 기준:** 분석 전후 등록 채널 수가 같다. 사용자가 등록 버튼을 누르기 전에는 저장되지 않는다.

### T0302. 채널 등록 확인

- **입력:** 채널 등록 버튼과 채널 정보.
- **동작:** 채널명·ID, 저장 폴더, 기본 품질·확장자를 확인한다.
- **출력:** 각 값과 `등록`, `취소`가 표시된다.
- **성공 기준:** 취소하면 저장되지 않는다. 필수 설정 오류가 있으면 등록할 수 없다.

### T0303. 등록 채널 저장·복원·중복 방지

- **입력:** 유효한 등록 설정과 등록 버튼.
- **동작:** 채널 ID와 설정을 저장하고 앱 시작 시 복원한다.
- **출력:** 등록 채널 표에 채널명, 현재 상태와 마지막 수동 확인 시각이 표시된다.
- **성공 기준:** 같은 채널 ID는 한 행만 존재한다. 앱 재실행 후 채널과 설정이 유지된다.

## S03.2 사용자는 등록 채널을 조회·수정·삭제한다

### T0304. 등록 채널 수동 새로고침

- **입력:** 선택 채널 또는 전체 새로고침 버튼.
- **동작:** 채널의 라이브·제목·카테고리·시청자 정보를 다시 조회한다.
- **출력:** 채널 표에 최신 방송 정보, 상태, 마지막 확인 시각이 표시된다.
- **성공 기준:** 자동 확인을 끈 채널도 수동으로 갱신된다. 한 채널 실패가 다른 채널 갱신을 막지 않는다.

### T0305. 등록 채널 수동 녹화

- **입력:** 등록 채널의 녹화 버튼.
- **동작:** 최신 라이브를 확인하고 E02의 녹화 설정·시작 흐름을 사용한다.
- **출력:** 오프라인 안내 또는 녹화 설정 화면이 표시된다.
- **성공 기준:** 별도 녹화 구현을 만들지 않고 기존 수동 녹화와 같은 작업 상태·중복 방지·중지를 사용한다.

### T0306. 채널 설정 수정

- **입력:** 등록 채널과 새 표시 이름·폴더·품질·확장자·자동 설정.
- **동작:** 입력을 확인하고 저장 시 채널 설정을 갱신한다.
- **출력:** 채널 행과 상세 화면에 새 설정이 표시된다.
- **성공 기준:** 취소하면 기존 값이 유지된다. 새 설정은 다음 작업부터 적용되고 실행 중 작업은 바뀌지 않는다.

### T0307. 채널 삭제

- **입력:** 채널 삭제와 진행 중 녹화 여부.
- **동작:** 녹화가 있으면 `중지 후 삭제`, `녹화 유지 후 목록 삭제`, `취소`를 제공한다.
- **출력:** 선택에 따라 채널 행이 제거되고 녹화가 중지되거나 유지된다.
- **성공 기준:** 취소는 아무것도 변경하지 않는다. 과거 작업 기록의 채널명은 유지된다.

### T0308. 채널 검색과 상태 필터

- **입력:** 검색어와 전체·라이브·오프라인·녹화 중·오류 필터.
- **동작:** 채널명·방송 제목 검색과 상태 조건을 함께 적용한다.
- **출력:** 일치 채널과 `전체 N개 중 M개`가 표시된다.
- **성공 기준:** 검색과 필터를 함께 사용하면 두 조건을 모두 만족한 채널만 보인다. 필터된 행의 작업 버튼이 정확한 채널에 적용된다.

# E04. 등록 채널 자동 확인과 조건 녹화

이 Epic이 끝나면 자동 확인을 켠 등록 채널만 주기적으로 갱신되고, 자동 녹화까지 켠 채널은 조건에 맞을 때 기존 녹화 흐름으로 녹화된다.

## S04.1 사용자는 등록 채널의 상태를 자동으로 갱신한다

### T0401. 자동 확인 주기와 활성 상태

- **입력:** 기존 등록 채널, 기본·채널별 확인 주기, 자동 상태 확인 체크와 자동 녹화 체크.
- **동작:** 등록·수정 화면에 두 자동 설정을 추가하고 양수 주기를 저장한다. 자동 녹화를 켜면 자동 상태 확인도 켠다.
- **출력:** 채널 행에 자동 확인·자동 녹화 상태와 마지막·다음 확인 시각이 표시된다.
- **성공 기준:** 자동 확인을 끈 채널은 자동 조회하지 않는다. 0·음수 주기는 저장되지 않는다.

### T0402. 주기적 채널 조회

- **입력:** 자동 확인 활성 채널과 현재 시각.
- **동작:** 확인 시각이 된 채널을 조회하고 라이브·제목·카테고리·태그·시청자 정보를 갱신한다.
- **출력:** 최신 상태와 조회 실패 여부가 채널 행에 반영된다.
- **성공 기준:** 같은 채널 조회가 겹치지 않는다. 한 채널 실패가 다른 채널 확인을 중단시키지 않는다.

### T0403. 라이브 시작·종료와 카테고리 변경 감지

- **입력:** 이전 정상 상태와 최신 정상 조회 결과.
- **동작:** 오프라인↔라이브와 라이브 중 카테고리 변경을 비교한다.
- **출력:** 채널 상세의 최근 상태 변경 목록에 이전·새 상태 또는 카테고리와 확인 시각이 한 번 기록된다.
- **성공 기준:** 동일 상태 반복은 이벤트를 만들지 않는다. 조회 오류·누락값을 종료나 변경으로 오인하지 않는다.

## S04.2 사용자는 자동 녹화 조건을 설정한다

### T0404. 카테고리·태그 조건

- **입력:** 포함·제외 카테고리, 포함·제외 태그와 현재 방송 정보.
- **동작:** 제외 조건을 우선 적용하고 포함 조건 충족 여부를 계산한다.
- **출력:** 일치·제외한 항목과 `녹화 대상/제외` 결과가 표시된다.
- **성공 기준:** 제외 하나라도 일치하면 녹화하지 않는다. 포함 목록이 비어 있을 때의 결과가 화면 설명과 일치한다.

### T0405. 시청자·팔로워·시간 조건

- **입력:** 최소·최대 시청자, 최소 팔로워, 허용 요일·시간과 현재 값.
- **동작:** 각 활성 조건을 비교해 항목별 결과를 계산한다.
- **출력:** 실제 값, 기준값, 충족·불충족과 최종 결과가 표시된다.
- **성공 기준:** 최소·최대와 같은 값의 포함 여부가 명확하다. 최소>최대는 저장되지 않는다. 자정을 넘는 시간 범위를 처리한다.

### T0406. 조건 미리보기

- **입력:** 편집 중인 조건과 현재 방송 또는 예시값.
- **동작:** 실제 자동 녹화와 같은 조건 판단을 실행한다.
- **출력:** `자동 녹화/녹화하지 않음`과 항목별 이유가 표시된다.
- **성공 기준:** 저장 후 같은 입력의 실제 판단과 미리보기 결과가 같다.

## S04.3 사용자는 조건 일치 방송을 자동 녹화한다

### T0407. 자동 녹화 시작

- **입력:** 오프라인→라이브 변화, 자동 녹화 활성, 조건 일치와 방송 ID.
- **동작:** 채널 설정으로 E02의 녹화 작업을 생성한다.
- **출력:** 작업 상세에 `자동 녹화`, 적용 조건과 방송 ID가 표시된다.
- **성공 기준:** 자동 상태 확인만 켠 채널은 녹화하지 않는다. 자동 녹화까지 켜고 조건이 맞은 채널만 시작한다.

### T0408. 자동·수동 중복 방지

- **입력:** 같은 방송 ID의 자동·수동 시작 요청과 현재 작업.
- **동작:** 기존 녹화가 있으면 새 프로세스를 만들지 않는다.
- **출력:** 기존 작업 ID와 시작 원인이 안내된다.
- **성공 기준:** 같은 방송에는 녹화 프로세스가 하나만 존재한다. 새 방송 ID는 이전 작업 종료 후 시작할 수 있다.

# E05. 여러 작업과 네트워크 사용량 제어

이 Epic이 끝나면 현재 앱에서 여러 VOD·녹화 작업을 제한된 개수로 실행하고 연결 수·속도·프록시를 설정할 수 있다.

## S05.1 사용자는 여러 작업을 한 목록에서 제어한다

### T0501. 작업 목록 상세와 재시도

- **입력:** VOD·녹화 작업과 상태 변경.
- **동작:** 종류, 대상, 상태, 진행률, 시각, 경로, 실패 이유를 한 표에 표시하고 실패 작업 재시도를 제공한다.
- **출력:** 최신순 작업 행과 작업 상세가 표시된다.
- **성공 기준:** 재시도는 원 기록을 유지하고 새 작업을 만든다. 파일이 이동·삭제돼도 기록은 유지하고 파일 없음으로 표시한다.

### T0502. 전체·종류별 동시 실행 제한

- **입력:** 전체, VOD, 녹화, 후처리 한도와 대기 작업.
- **동작:** 전체 한도와 종류 한도를 모두 만족할 때 다음 작업을 시작한다.
- **출력:** 종류별 `실행 N/한도 M`, 대기 순서와 대기 이유가 표시된다.
- **성공 기준:** 실행 수가 한도를 넘지 않는다. 하나가 끝나면 가능한 다음 대기 작업이 시작된다. 한도를 낮춰도 실행 중 작업을 강제 종료하지 않는다.

## S05.2 사용자는 연결 수·속도·프록시를 설정한다

### T0503. 최대 연결 수와 속도 제한

- **입력:** 작업당 연결 수, 전체·작업별 속도와 단위.
- **동작:** 정상값을 지원 외부 도구 실행에 적용한다.
- **출력:** 작업 시작 전에 실제 적용 연결 수와 속도 또는 `지원하지 않음`이 표시된다.
- **성공 기준:** 0·음수·잘못된 단위는 저장되지 않는다. 지원하지 않는 도구에 적용된 것으로 표시하지 않는다.

### T0504. 프록시 설정과 연결 확인

- **입력:** 직접·시스템·사용자 지정 방식, scheme·host·port와 선택 인증값.
- **동작:** 입력을 확인하고 치지직 조회 연결을 시험한 뒤 저장한다.
- **출력:** 연결 성공·실패, 응답 시간과 실패 이유가 표시된다.
- **성공 기준:** 실패한 시험이 기존 정상 설정을 덮어쓰지 않는다. 정상 프록시는 정보 조회와 지원 작업에 적용된다.

### T0505. GoodbyeDPI 선택 실행

- **입력:** 실행 파일 경로와 사용자의 시작·중지 선택.
- **동작:** 사용자가 시작한 경우에만 실행하고 프로그램이 시작한 프로세스만 중지한다.
- **출력:** `사용 안 함/중지/실행 중/실패`가 표시된다.
- **성공 기준:** 기본 상태에서는 실행되지 않는다. 실패가 다른 네트워크 기능을 종료시키지 않는다.

# E06. VOD·녹화 세부 제어

이 Epic이 끝나면 기존 다운로드·녹화 흐름에서 구간, 분할, 이어받기, 녹화 형식과 재연결을 사용할 수 있다.

## S06.1 사용자는 VOD 구간과 분할 방식을 선택한다

### T0601. 구간 다운로드

- **입력:** 시작·종료 시각과 VOD 전체 길이.
- **동작:** `0 ≤ 시작 < 종료 ≤ 전체 길이`를 확인해 기존 다운로드 작업에 구간을 적용한다.
- **출력:** 선택 구간·길이와 구간 결과 파일이 표시된다.
- **성공 기준:** 잘못된 시간은 시작 전에 거부된다. 결과 길이가 요청 구간과 허용 오차 안에 있다.

### T0602. 시간·용량 기준 분할

- **입력:** 대상 구간과 시간 간격 또는 목표 용량.
- **동작:** 조각 범위를 계산해 순번이 있는 파일을 생성한다.
- **출력:** 예상·실제 조각 수와 조각별 시간·크기·경로가 표시된다.
- **성공 기준:** 값은 0보다 커야 한다. 모든 조각을 순서대로 재생하면 대상 전체 범위를 덮는다.

### T0603. 중복·부분 파일 처리

- **입력:** URL·품질·구간·경로와 기존 진행 작업·부분 파일.
- **동작:** 동일 진행 작업은 막고 부분 파일은 이어받기·처음부터·취소를 선택한다.
- **출력:** 기존 작업 또는 부분 파일 크기와 가능한 행동이 표시된다.
- **성공 기준:** 동일 진행 작업은 하나다. 불완전 파일은 완료로 표시되지 않고 확인 없이 삭제되지 않는다.

## S06.2 사용자는 녹화 품질·형식과 끊김 처리를 설정한다

### T0604. 채널별 품질·확장자·파일명

- **입력:** 전역·채널 품질, 확장자, 채널명·제목·날짜·방송 ID 파일명 형식.
- **동작:** 채널 설정을 우선 적용하고 실제 품질·형식·파일명을 결정한다.
- **출력:** 녹화 전에 실제 적용값과 최종 경로가 표시된다.
- **성공 기준:** 결과 해상도와 컨테이너가 적용값과 일치한다. 금지 문자를 처리하고 기존 파일을 자동 덮어쓰지 않는다.

### T0605. 연결 끊김 감지와 제한 재연결

- **입력:** 마지막 데이터 시각, 최신 라이브 상태, 최대 횟수와 간격.
- **동작:** 방송 종료와 연결 실패를 구분하고 라이브이면 새 스트림으로 제한 재연결한다.
- **출력:** `방송 종료/연결 끊김/재연결 N/M`, 다음 시도와 조각 파일이 표시된다.
- **성공 기준:** 방송 종료에는 재연결하지 않는다. 최대 횟수를 넘지 않고 무한 대기하지 않는다.

### T0606. 반복 시작·중지 확인

- **입력:** 같은 테스트 방송의 시작·중지 반복.
- **동작:** 작업별 외부 프로세스와 파일을 종료하고 다음 작업을 시작한다.
- **출력:** 반복마다 별도 작업 ID·상태·파일이 표시된다.
- **성공 기준:** 10회 반복 후 새 녹화를 시작할 수 있고 종료 프로세스가 남거나 작업 상태가 섞이지 않는다.

# E07. 미등록 방송을 조건으로 발견하고 녹화

이 Epic이 끝나면 사용자는 등록하지 않은 현재 방송을 조건으로 찾고 한 번 녹화·채널 등록·무시를 선택할 수 있다.

## S07.1 사용자는 현재 방송을 조건으로 찾는다

### T0701. 현재 방송 목록 조회·중지

- **입력:** 탐색 시작·중지, 자동 탐색 간격과 최대 조회 수.
- **동작:** 현재 방송을 페이지별로 가져오고 방송 ID 중복을 제거하며 중지 시 다음 페이지 요청을 멈춘다.
- **출력:** 현재 페이지, 받은 방송 수, 마지막·다음 탐색 시각이 표시된다.
- **성공 기준:** 마지막 페이지에서 끝나고 같은 방송은 한 행만 표시된다. 이전 탐색과 겹치지 않는다.

### T0702. 탐색 조건 저장과 적용

- **입력:** 조건 이름, 카테고리, 포함·제외 태그, 최소·최대 시청자, 최소 팔로워.
- **동작:** 조건을 저장하고 방송별 일치 여부와 이유를 계산한다.
- **출력:** 조건 목록과 일치 방송의 실제값·기준값·일치 이유가 표시된다.
- **성공 기준:** 제외 조건을 우선한다. 최소·최대와 같은 값의 포함 여부가 명확하다. 앱 재실행 후 조건이 유지된다.

## S07.2 사용자는 발견 방송의 녹화 여부를 선택한다

### T0703. 발견 목록과 순차 팝업

- **입력:** 처음 조건에 일치한 방송.
- **동작:** 목록에 추가하고 표시 중 팝업이 없을 때만 새 팝업을 연다.
- **출력:** 썸네일, 제목, 채널, 카테고리, 태그, 시청자, 팔로워, 일치 이유와 행동 버튼이 표시된다.
- **성공 기준:** 팝업은 한 번에 하나다. 닫은 방송도 발견 목록에서 다시 볼 수 있다.

### T0704. 한 번 녹화·등록 후 녹화·무시

- **입력:** 사용자의 행동 선택과 방송·채널 정보.
- **동작:** 최신 라이브를 다시 확인해 기존 녹화·채널 등록 흐름을 실행하거나 선택 범위로 무시한다.
- **출력:** 생성된 작업·채널 또는 무시 종류와 만료 시각이 표시된다.
- **성공 기준:** 채널·작업 중복을 만들지 않는다. 같은 방송 팝업은 제한 시간 안에 반복되지 않고 새 방송 ID는 정상 알린다.

# E08. 앱·데스크톱·메신저 알림

이 Epic이 끝나면 기존 라이브·카테고리·작업 이벤트가 사용자가 선택한 알림 수단으로 전달된다.

## S08.1 사용자는 앱과 데스크톱에서 이벤트를 확인한다

### T0801. 앱 내부 알림 목록

- **입력:** 라이브 시작·종료, 카테고리 변경, 작업 완료·실패, 공간 부족 이벤트.
- **동작:** 읽음 상태와 관련 채널·작업을 가진 알림을 만든다.
- **출력:** 시각, 종류, 제목, 요약, 읽음 여부와 관련 화면 열기가 최신순으로 표시된다.
- **성공 기준:** 새 알림 수가 읽지 않은 수와 같다. 같은 이벤트가 중복 생성되지 않는다.

### T0802. 데스크톱 팝업과 행동

- **입력:** 데스크톱 알림이 활성화된 이벤트와 사용자의 녹화·보기·무시 선택.
- **동작:** 운영체제 알림을 표시하고 행동 시 최신 상태를 다시 확인한다.
- **출력:** 앱 밖에서도 사건 종류와 대상이 보이고 선택 결과가 앱에 반영된다.
- **성공 기준:** 오래된 팝업으로 오프라인 방송 녹화를 만들지 않는다. OS 알림 실패 시 앱 내부 알림은 유지된다.

## S08.2 사용자는 Telegram·Discord로 선택 이벤트를 받는다

### T0803. Telegram 설정과 이벤트 전송

- **입력:** bot token, chat ID, 시험·실제 이벤트.
- **동작:** 시험 성공 설정을 저장하고 선택 이벤트를 메시지로 보낸다.
- **출력:** 시험·전송 성공 또는 인증·chat·제한·네트워크 오류가 표시된다.
- **성공 기준:** 실패 설정이 정상 설정을 덮어쓰지 않는다. 전송 실패가 원래 작업 상태를 실패로 바꾸지 않는다.

### T0804. Discord 설정과 이벤트 전송

- **입력:** webhook과 시험·실제 이벤트.
- **동작:** 시험 성공 webhook을 저장하고 길이·mention을 처리해 메시지를 보낸다.
- **출력:** 시험·전송 결과와 Discord 메시지가 표시된다.
- **성공 기준:** 긴 제목 때문에 전체 전송이 실패하지 않고 `@everyone/@here`가 전체 mention을 발생시키지 않는다.

### T0805. 이벤트별 수단 선택과 실패 재전송

- **입력:** 이벤트별 앱·데스크톱·Telegram·Discord 체크와 실패 알림 재전송.
- **동작:** 활성 수단에만 한 번 전달하고 실패는 수동 재시도한다.
- **출력:** 수단별 전송 상태, 마지막 시각·시도 횟수가 표시된다.
- **성공 기준:** 비활성 수단은 호출하지 않는다. 재전송 성공 시 상태가 갱신되고 무한 자동 재시도하지 않는다.

# E09. 녹화 결과 후처리와 파일 관리

이 Epic이 끝나면 사용자는 기존 녹화 파일을 확인·병합·변환·인코딩·분할·이동하고 목록에서 관리할 수 있다.

## S09.1 사용자는 녹화 결과를 확인하고 조각을 병합한다

### T0901. 결과 파일 상태 확인

- **입력:** 완료·중단 작업의 결과 경로.
- **동작:** 파일 존재·크기·재생 시간·영상·음성을 확인한다.
- **출력:** `정상/파일 없음/0바이트/읽기 실패/영상 없음/음성 없음`과 상세값이 표시된다.
- **성공 기준:** 파일 존재만으로 정상 판정하지 않고 확인 실패가 원본을 변경하지 않는다.

### T0902. 조각 순서 확인과 병합

- **입력:** 같은 작업의 조각 순번·시각·파일과 결과 경로.
- **동작:** 누락·중복·손상을 확인해 정상 조각을 순서대로 병합하고 결과를 다시 확인한다.
- **출력:** 조각 표, 병합 진행률, 결과 재생 시간·경로가 표시된다.
- **성공 기준:** 문제 조각이 있으면 병합하지 않는다. 결과 확인 전 원본을 삭제하지 않고 실패 시 모두 유지한다.

## S09.2 사용자는 결과를 변환·분할·정리한다

### T0903. 컨테이너 변환과 인코딩

- **입력:** 원본, 목표 컨테이너, 영상·음성 codec과 품질 설정.
- **동작:** 호환 시 stream copy, 그 외 인코딩을 실행하고 진행률을 표시한다.
- **출력:** 처리 방식, 진행률, 결과 codec·컨테이너·재생 시간이 표시된다.
- **성공 기준:** 실제 결과 형식이 선택값과 일치한다. 취소·실패 시 불완전 파일을 완료로 표시하지 않고 원본을 유지한다.

### T0904. 후처리 분할·이동·공간 확인

- **입력:** 결과 파일, 시간·용량 분할값, 폴더 규칙과 남은 공간.
- **동작:** 공간을 먼저 확인하고 분할한 뒤 채널·날짜·작업 종류 폴더로 이동한다.
- **출력:** 예상 공간, 조각 목록, 이동 전·후 경로가 표시된다.
- **성공 기준:** 공간 부족 시 시작하지 않는다. 전체 재생 범위를 빠뜨리지 않고 이동 실패 시 원본 위치를 유지한다.

### T0905. 생성 파일 목록과 삭제

- **입력:** 작업 결과·조각·부분 파일과 삭제 선택.
- **동작:** 파일명·크기·길이·상태를 표시하고 진행 중 파일을 제외한 선택 파일을 확인 후 삭제한다.
- **출력:** 파일 목록, 폴더 열기, 삭제 대상·전체 크기와 처리 결과가 표시된다.
- **성공 기준:** 취소하면 삭제하지 않는다. 선택 밖 파일과 진행 중 파일을 삭제하지 않는다.

# E10. 시스템 상태와 백그라운드 실행

이 Epic이 끝나면 사용자는 현재 앱의 자원 상태를 보고 공간 부족을 처리하며 tray에서 기존 작업을 계속할 수 있다.

## S10.1 사용자는 PC와 저장 공간 상태를 확인한다

### T1001. CPU·메모리·네트워크·디스크 표시

- **입력:** 시스템과 앱 프로세스의 CPU·메모리, 송수신 누적량, 저장 폴더 드라이브 값.
- **동작:** 설정 간격마다 사용률·속도·용량을 계산한다.
- **출력:** 전체·앱 CPU, 전체·앱 메모리, 다운로드·업로드 속도, 드라이브 전체·남은 공간과 갱신 시각이 표시된다.
- **성공 기준:** 조회 실패 항목만 `확인 불가`로 표시하고 다른 값과 작업은 계속 갱신된다.

### T1002. 공간 부족 경고

- **입력:** 새 작업 대상 드라이브 남은 공간과 최소 여유 공간.
- **동작:** 작업 시작 전에 비교해 기준 이하이면 확인창을 표시한다.
- **출력:** 작업 종류, 남은 공간, 최소 요구량과 `그래도 시작/취소`가 표시된다.
- **성공 기준:** 사용자 선택 전 작업을 만들지 않는다. 진행 중 녹화를 예고 없이 강제 종료하지 않는다.

## S10.2 사용자는 앱을 tray에서 계속 실행하고 안전하게 종료한다

### T1003. Tray 최소화와 복원

- **입력:** tray로 보내기와 tray 메뉴의 열기.
- **동작:** 기존 창을 숨기고 복원한다.
- **출력:** tray 메뉴에 열기, 실행 작업 수, 종료가 표시된다.
- **성공 기준:** tray에서도 자동 확인과 작업이 계속되고 복원 시 창이 여러 개 생기지 않는다.

### T1004. 작업 중 종료 선택과 프로세스 정리

- **입력:** 작업 중 창 닫기와 `계속/중지 후 종료/취소` 선택.
- **동작:** 선택에 따라 tray 유지 또는 프로그램이 시작한 외부 작업 종료와 상태 저장을 수행한다.
- **출력:** 실행 작업 수와 정리 상태가 표시되고 다음 실행 시 중단 작업이 표시된다.
- **성공 기준:** 취소는 상태를 유지한다. 앱 소유 프로세스만 종료하고 사용자가 별도 실행한 프로세스는 건드리지 않는다.

# E11. 도구 갱신·플러그인·오류 복구

이 Epic이 끝나면 사용자는 개인 PC의 외부 도구를 갱신하고 선택 플러그인을 사용하며 주요 오류 후 기존 앱을 계속 사용할 수 있다.

## S11.1 사용자는 외부 도구 경로와 버전을 관리한다

### T1101. 외부 도구 통합 설정

- **입력:** FFmpeg·Streamlink 실행 파일 선택과 앱에 포함된 yt-dlp Python 패키지.
- **동작:** 외부 실행 파일은 종류·실행 가능·버전을 확인해 정상 경로만 저장하고, yt-dlp는 설치된 패키지 버전과 상태를 확인한다.
- **출력:** 외부 도구별 경로·버전·상태와 yt-dlp 패키지 버전·상태, 각 도구를 사용하는 기능이 표시된다.
- **성공 기준:** 다른 종류·실행 불가 외부 파일은 저장되지 않고 다음 작업은 선택 경로를 사용한다. yt-dlp는 사용자가 실행 파일 경로를 선택하지 않으며 앱에 포함된 Python 패키지를 사용한다.

### T1102. 외부 도구 갱신

- **입력:** 갱신 도구 선택.
- **동작:** 새 파일을 준비하고 사용 중이 아닐 때 교체한 뒤 버전을 다시 확인한다.
- **출력:** 진행 상태와 갱신 전·후 버전 또는 실패 이유가 표시된다.
- **성공 기준:** 사용 중 도구를 교체하지 않는다. 갱신 실패 시 기존 실행 가능 도구를 계속 사용한다.

## S11.2 사용자는 선택형 플러그인을 켜고 끈다

### T1103. 플러그인 목록과 작업 완료 플러그인

- **입력:** 확인 가능한 Python 플러그인과 활성 선택, 완료 작업 정보.
- **동작:** 플러그인을 켜고 끄며 예제 플러그인은 완료 결과 옆에 요약 텍스트를 만든다.
- **출력:** 이름, 설명, 활성 상태, 마지막 결과와 생성 요약 파일이 표시된다.
- **성공 기준:** 활성 플러그인만 실행되고 앱 재실행 후 상태가 유지된다. 실패·취소 작업에는 요약을 만들지 않는다.

### T1104. 플러그인 오류 분리

- **입력:** 플러그인 예외·시간 초과.
- **동작:** 해당 플러그인만 실패 처리한다.
- **출력:** 원 작업 완료와 플러그인 실패·이름·오류가 별도로 표시된다.
- **성공 기준:** 플러그인 오류가 원 작업과 다른 작업 상태를 바꾸거나 GUI를 멈추지 않는다.

## S11.3 사용자는 실패 원인을 확인하고 복구한다

### T1105. 작업 오류 상세와 재시도

- **입력:** 네트워크, 인증, 설정, 공간, 외부 도구 실패.
- **동작:** 오류 종류·대상·시각·요약·수정 행동과 재시도 가능 여부를 표시한다.
- **출력:** 오류 상세와 설정 열기·다시 시도 버튼이 표시된다.
- **성공 기준:** 사용자가 확인할 항목을 구분할 수 있고 재시도는 원 기록을 유지한 새 작업으로 생성된다.

### T1106. 저장 데이터 오류와 반복 조작 복구

- **입력:** 읽을 수 없는 설정·채널·작업 데이터 또는 시작·취소·재시도 연속 클릭.
- **동작:** 읽을 수 있는 데이터로 앱을 시작하고 처리 중 중복 행동을 막는다.
- **출력:** 읽지 못한 데이터 종류·영향 범위와 한 작업당 하나의 현재 상태가 표시된다.
- **성공 기준:** 한 데이터 오류 때문에 앱 전체가 시작 실패하지 않는다. 화면 실행 작업 수와 실제 관리 프로세스 수가 일치한다.
